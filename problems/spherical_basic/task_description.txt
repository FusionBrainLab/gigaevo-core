SPHERICAL CODES — IMPROVE A WARM-START CONFIGURATION ON ANY (n, d)

Objective: place n unit vectors in R^d that minimize the maximum pairwise inner product
  mu(X) = max_{i<j} <x_i, x_j>        (lower mu is better)

Regime: the grader never cold-starts. It seeds each evaluation with a strong
best-known configuration and measures how much solve() lowers mu
below that baseline. You are floored at the baseline — non-improvement scores
zero, never negative.

Generality: the class must work for any n >= 2 and any d >= 2. No hardcoded
dimensions, point counts, shapes, or branches tied to a single (n, d).

THE GRADER (per configuration)
- current = best-known config;  baseline = mu(current)
- solve(current) is called repeatedly until the total wall-clock budget is spent
  each returned configuration is accepted only if it lowers mu
  acceptance is monotone: mu can only decrease; ties accepted, regressions discarded
- per-config score = relative reduction of mu vs the baseline, clamped at zero
A raised exception costs only that one call (that one solve call). The run aborts
only if no configuration ever returns a valid array.
There is a generous per-configuration time budget. Spend it on depth: more
restarts, finer convergence, and deeper search inside each solve call all push mu lower.
The grader keeps the best configuration any completed solve() call
returns, so a longer, deeper search never costs score; prefer an anytime
optimizer that keeps lowering mu over one that returns early.

HARD CONSTRAINTS
- output shape exactly (n, d)
- unit rows: max_k | norm(x_k) - 1 | <= 1e-12   (float32 round-off ~1e-7 fails; use float64)
- no NaN, no Inf

REQUIRED CLASS — exact signature

import numpy as np

class Solver:
    def __init__(self, n: int, d: int, seed: int = 0): ...
    def solve(self, points: np.ndarray, seed=None) -> np.ndarray: ...

def entrypoint():
    return Solver

Implement a Python class with one method:

solve(points, seed=None)

- You receive the best-known configuration. Return one with lower mu.
- The evaluator calls solve repeatedly within ONE total wall-clock budget and keeps the best valid result. A single call may use all the time that remains.
- seed differs on every call. A different seed must explore a different solution, or the repeated calls all recompute one answer and the budget is wasted.
- There is no separate perturb operator and no intensity schedule. Any escape from a local optimum has to happen inside solve. State kept on self persists across calls, so managing your own search is your job.
- The outer evaluator independently validates every candidate and accepts only feasible improvements.
- Return (n, d) unit-norm.

Perturbation ideas that tend to work: target the active set (the pairs realizing
the current maximum); relax through a smooth surrogate of the max (LogSumExp,
Riesz s-energy) then sharpen; move on the sphere geometry (tangent steps,
geodesic updates, subset rotations); orchestrate these yourself, across and within repeated solve calls.
