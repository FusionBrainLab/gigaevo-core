**TASK DEFINITION – SIZE-GENERALIZING HEXAGON PACKING OPTIMIZER**

**Challenge:** Implement a Python class that minimizes the side length of a flat-topped regular enclosing hexagon required to contain $N$ non-overlapping unit regular hexagons — for EVERY evaluated $N$, not a single one.

**Benchmark Set:** Each evaluation grades your class INDEPENDENTLY at five sizes: $N \in \{11, 12, 15, 17, 23\}$.
**General Requirement:** The code must be valid for any $N$ from 1 to 30. Additional held-out sizes are graded after evolution, so size-specific hardcoding generalizes badly.

**GEOMETRIC SPECIFICATIONS**
1.  **Unit Hexagons (Items):**
    *   Regular hexagons with circumradius $r = 1.0$.
    *   Side length = 1.0.
    *   May be arbitrarily placed $(x, y)$ and rotated $(\theta)$.
2.  **Enclosing Hexagon (Container):**
    *   Regular, flat-topped, centered at $(0,0)$.
    *   "Flat-topped" vertices are located at angles $[0^\circ, 60^\circ, 120^\circ, 180^\circ, 240^\circ, 300^\circ]$ relative to the center.
    *   Objective: Minimize the enclosing hexagon's side length $L$ (which is equal to its circumradius).

**OBJECTIVE FUNCTION**
Each size $N$ yields the side length $L_N$ of the best valid configuration your class produced at that size; a size with no valid configuration counts as invalid.
Maximize Fitness: $-\big(\mathrm{mean}_{\text{valid } N}\; L_N/\sqrt{N} \;+\; \#\{\text{invalid } N\}\big)$.
$L/\sqrt{N}$ normalizes scale so every size contributes comparably. Each invalid size costs a full penalty point, so producing SOME valid packing at every size dominates perfecting a single one. Per-size results are reported back to you as fitness_11 ... fitness_23.

**CONSTRAINTS**
1.  **Containment:** All vertices of every unit hexagon must lie inside or on the boundary of the enclosing hexagon.
2.  **Non-overlap:** The intersection area between any pair of unit hexagons must be zero (touching is allowed).
3.  **Count:** Exactly `hex_num` unit hexagons must be placed.

**EVALUATION BUDGET**
Each of the five sizes gets its own equal, SHORT wall-clock slice — tens of seconds, far less than a leisurely single-instance budget. Within a slice the evaluator calls your class repeatedly, independently validates every configuration it hands back, and keeps the best valid one for that size. The cost of a call is a real cost: a cheap call buys more calls, and at these budgets a single expensive call can consume the whole slice and leave that size invalid. Fast convergence at every size matters as much as asymptotic quality at one.

**CRITICAL FAILURE MODES**
*   **Wrong Shapes:** Returning arrays of shape `(12, ...)` when `hex_num=11`.
*   **Geometry Errors:** Assuming point-topped enclosing hexagon instead of flat-topped.
*   **Invalid Output:** Hexagons overlapping or protruding outside the boundary in the final result.
*   **Single-Size Specialization:** layouts or constants tuned to one $N$ — the score is a MEAN over five sizes, and held-out sizes follow after evolution.
*   **Slice Overrun:** a first call slower than the per-size slice returns nothing, and that size scores invalid.
*   **Seed-Blind Solver:** Hardcoding a fixed RNG seed (e.g. `np.random.seed(42)`) so that every call returns the identical configuration. The evaluator calls solve repeatedly; identical answers waste the entire slice.
